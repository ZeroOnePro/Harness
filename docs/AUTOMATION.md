# 일일 하네스 자동화: 중앙 관리와 비공개 프로젝트 연동

- 중앙 저장소: `ZeroOnePro/Harness` (공개).
- 적용 대상: 현재 연결된 비공개 개인 프로젝트 4개. 비공개 저장소 이름과 세부 실패 기록은 이 공개 문서에 기록하지 않는다.
- 대상 프로젝트의 `.github/workflows/daily-harness.yml`은 중앙의 재사용 워크플로를 `@main`으로 호출한다.
- 각 프로젝트는 `.harness/COMMON_RULES.md`를 중앙 `shared/COMMON_RULES.md`에서 동기화한다. 프로젝트별 `AGENTS.md`가 그 파일을 참조한다.
- 매일 00:00 UTC = 한국시간 09:00 실행. GitHub schedule은 부하에 따라 늦어지거나 건너뛸 수 있다. 수동 실행은 workflow_dispatch로 가능하다.
- 실패 인벤토리는 **비공개 프로젝트의 Workflow Artifact**에만 저장하고 원본 로그는 임시 처리 후 삭제한다. 중앙 공개 저장소로 개인정보·기밀·작업 로그를 전송하지 않는다.
- 중앙 일일 작업은 원본 해시(9개), 상대 링크, 스킬 형식 검증이다. 현재 외부 모델 기반 Agent Evals나 근본원인 자동 수정은 구현되지 않았다.
- 프로젝트 예약 수집기는 실제 실패 로그를 임시 처리해 비공개 식별 신호를 수집한다. PR 및 push의 기존 메타데이터 검사는 로그 본문을 가져오지 않는다.
- 결과물이 실제 테스트 성능을 입증하지는 않는다. 실패 단계별 재현 테스트와 인간의 판단이 필요한 원인 분석은 별도로 수행해야 한다.
- 다른 레포의 기존 요구사항·도구별 정책은 유지하며 공유 규칙에 의해 완화되지 않는다.
- `@main`을 사용한 최신 중앙 하네스 자동 적용은 공급망 위험을 수반한다. 중앙 저장소 쓰기 권한을 제한하고 중요한 변경은 리뷰해야 한다.
- GitHub Actions의 `GITHUB_TOKEN`이 대상 프로젝트 contents:write를 부여받을 수 있어야 공유 규칙의 자동 커밋이 가능하다. 브랜치 보호 정책이 차단하면 자동 동기화가 실패하며, 수동 PR 적용이 필요하다.
- 신규 프로젝트를 추가하려면 각 프로젝트에 프로젝트 워크플로와 AGENTS 참조를 설치해야 한다. 모든 71개 소유 저장소에 임의로 적용하지 않는다.

## 피드백을 중앙 개선에 사용하는 방법

비공개 `private-harness-evidence` 아티팩트에 run/attempt/job별 인벤토리와 반복 실패 식별 신호가 저장된다. 반복된 유형을 실제 재현 테스트로 바꾼 뒤 **민감 정보가 없는 일반화된** eval 사례만 이 공개 저장소에 PR로 추가한다. 원본 로그를 공개 저장소의 이슈나 PR에 첨부하지 않는다.

향후 완전 자동 교차 저장소 집계를 원한다면 중앙 Harness의 비공개 전환 또는 별도 비공개 평가 저장소와 GitHub App의 최소권한 인증을 먼저 구성해야 한다. 공개 저장소로의 무단 로그 복제는 금지한다.

## 비공개 프로젝트의 예약 증거 수집

공개 중앙 워크플로는 원본 무결성, 스킬, 링크 및 합성 회귀 테스트만 검증한다. 공개 저장소에서 비공개 저장소용 토큰을 요구하거나 교차 저장소 실패를 분석하지 않는다.

기존 재사용 워크플로는 비공개 호출 저장소의 기본 브랜치에서 실행되는 schedule 또는 workflow_dispatch에 한하여, 기존 Actions/Contents 읽기 권한과 해당 실행의 GITHUB_TOKEN으로 실패 run/job 및 실제 로그를 수집한다. 원본 로그와 선택적 실패 기록은 실행기 임시 디렉터리에서만 처리하고 삭제한다. 원문, 경로, 오류 메시지 또는 코드 대신 run/attempt/job 식별자, 수집 상태 및 비공개 fingerprint가 포함된 `private-harness-evidence` 아티팩트를 호출 저장소에만 30일 보존한다. 이 아티팩트를 공개 저장소로 전송하지 않는다.

필수 데이터 조회가 실패하면 수집 단계는 0이 아닌 종료 코드로 종료한다. 원인 분석이 미완료라는 상태는 수집 성공과 구분한다. PR 이벤트에서는 새 로그 수집을 수행하지 않는다. 기존 프로젝트 워크플로의 공유 규칙 동기화와 사용자 권한은 변경하지 않는다.

GitHub 스케줄이 늦어질 수 있으므로 교차 저장소 분석기는 최신 실행 증거를 REST GET으로 직접 확인하고, 아티팩트가 생성됐다는 이유만으로 원인 분석이 완료됐다고 판단하지 않는다. 신규 후보의 원인 분석, 합성 재현, 중복 비교와 검토용 PR 작성은 별도의 비공개 분석 세션에서 수행한다. 자동 병합하지 않는다.

로컬 수집과 검증 방법은 [증거 기반 실패 점검](EVIDENCE_AUDIT.md)을 참조한다.
