# 동작을 보존하는 단순화

검토 요청이면 근거와 수정안을 보고한다. 정리·수정 요청이면 범위 안에서 변경하고 기존 동작과 필수 제약이 보존되는지 확인한다. 개선할 근거가 없으면 변경하지 않아도 된다.

## 삭제·통합 후보 찾기

- 현재 diff와 직접 관련된 구현·호출자부터 확인한다. 저장소 전체 정리로 범위를 넓히지 않는다.
- 같은 이유로 함께 바뀌는 정책이 여러 곳에 구현됐는지 확인한다. 모양이 비슷해도 서로 다른 도메인 규칙이면 통합하지 않는다.
- 실제 호출 경로에서 역할이 없는 전달 계층, 현재 요구에 쓰이지 않는 확장 지점, 중복 분기와 설정을 후보로 삼는다. 공개 API·외부 호출·직렬화·호환성·동적 사용 여부를 확인하기 전에는 미사용으로 단정하지 않는다.
- 하네스 문서는 시작 지침, 상세 절차, 평가 기록, 보관 원본의 역할을 구분한다. 상세 규칙은 한 곳에 두고 읽는 조건과 경로를 연결한다. 출처·권한·검증 기준을 단순 반복 문구로 취급해 삭제하지 않는다.

## 가장 좁은 변경 선택

- 후보마다 위치, 유지보수 문제, 제거·통합 방법, 보존할 동작, 확인 방법을 설명한다. 취향이나 줄 수만으로 문제를 만들지 않는다.
- 삭제나 기존 구현 재사용으로 해결할 수 있는지 먼저 본다. 중복을 없애려는 새 추상화가 호출자의 옵션·분기·결합도를 늘리면 기존 분리를 유지한다.
- 오류 처리, 타입 검사, 접근성, 권한, 테스트는 실제 불필요함을 입증하지 않은 채 제거하지 않는다. 원본 보존 대상은 편집하지 않고 개정본이나 보완 문서를 사용한다.
- 동작 변경이 필요한 후보는 단순화와 구분해 보고한다. 현재 요청이 허용하지 않으면 그 후보는 변경하지 않는다.

## 결과 확인

- 관련 검사와 실제 호출·문서 참조 경로를 확인한다. 삭제한 심볼의 참조, 사라진 검증, 바뀐 외부 계약이 없는지 살핀다.
- 무엇을 줄였고 어떤 동작을 확인했는지 보고한다. 실행하지 못한 검사는 미검증으로 남긴다. 줄 수 감소를 성능·토큰 절감 증거로 쓰지 않는다.

이 스킬은 코드·지침 정리를 위한 독립 작성본이다. pstack의 [unslop](https://github.com/backnotprop/pstack/blob/25abb38559ddbabec563646224d09eff9a250eca/skills/unslop/SKILL.md)은 글의 표현을 다듬는 스킬이므로 이름과 기능을 구분한다.
